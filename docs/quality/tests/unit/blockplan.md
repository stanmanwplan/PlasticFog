# pf_BlockPlan_Tests

<!-- dc:status=polished dc:owner=DC4b -->

Source: `tests/unit/pf_BlockPlan_Tests.cpp` · CTest: `pf_BlockPlan` · Labels: `unit;fast;public`

This test pins the name-to-block rules: given a Zimpl symbol table, the list of
subproblem service ids, an MPS model and a block assignment, the unit produces
the `.block` file the decomposition solver reads, together with the name maps
and the per-block reduced-cost index. Its oracles are checked-in runtime
artifacts, so feeding two of the three files back in and comparing the third is
a round trip rather than a restatement of the same rules.

## What it verifies

- For the captured flat case, the generated `.block` text is byte-equal to the
  committed capture, exactly one column is identified as belonging to no block
  — the master's own — and that column is broadcast into every block's
  reduced-cost index.
- Abbreviated MPS column names resolve through the symbol table: the name maps
  are keyed by full, unquoted name, and the abbreviation-to-full-name map
  carries the Zimpl abbreviation.
- For the nested case the test pins a known discrepancy rather than editing the
  fixture: the generated bytes are asserted literally, and the committed file is
  shown to be those same bytes with record order sorted by block number and the
  row-list trailing spaces removed — differing in no other byte. The
  block-to-row association the fixture is an oracle for is asserted separately
  and is correct.
- At a mid-level node, the columns belonging to no block are the interface
  columns its parent prices; all three are named, and each child cell gets its
  own reduced-cost index block.
- Six refusals are checked: an unrecognised service id in a constraint row, an
  id with no block assignment, an empty table file, an absent service-id file,
  an unbalanced quote in a full name, and an MPS column the table does not
  declare.

## Running

```bash
ctest --test-dir build -R '^pf_BlockPlan$' --output-on-failure
```

The target exists only in a tree configured with `-DPF_BUILD_UNIT_TESTS=ON`.
